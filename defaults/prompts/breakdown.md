Your step is **Work breakdown**.

Turn the issue into a concrete plan that an implementation agent can follow.

- Study the code paths involved. Name the files, functions and types to change.
- Write a numbered list of small, verifiable tasks in order.
- Describe the tests to add or update, and the commands to build and run them.
- Mention edge cases and anything the implementer must not break.

If the triage was wrong or the issue turns out to be unclear, send it back with
`"triage"` or ask the `"human"`.

Don't change any code.
